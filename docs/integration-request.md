# 【依頼】不具合報告アプリからの報告を、店舗コミュニケーションアプリで受け取れるようにしたい

並行して運用している **不具合報告アプリ（現場トラブル・不具合クイック報告）** から送られた報告を、
この店舗コミュニケーションアプリ側で受け取って表示・通知できるようにしたいです。

**このチャットにお願いしたいのは「実装」ではなく「回答」です。**
下の「回答してほしいこと」に答えてください。その内容をもとに、送る側（不具合報告アプリ）を私の方で実装します。
すでにそちらで実装できる部分があれば、それも教えてください。

---

## 1. 送る側（不具合報告アプリ）の現状

そちらの設計判断に必要な事実だけを挙げます。

| 項目 | 内容 |
|---|---|
| 形態 | 単一 HTML の静的サイト（GitHub Pages 配信）。ビルドもサーバーもなし |
| Firebase プロジェクト | `store-trouble-report` |
| Firestore | コレクション `trouble_reports` / リージョン `asia-northeast1` |
| 料金プラン | **Spark（無料）**。Cloud Functions も Cloud Storage も使えない |
| 認証 | Firebase Auth のメール／パスワード。店舗コードをそのまま ID とパスワードに使う（例: `fm0001` → `fm0001@fm.example.com`） |
| 写真 | Storage を使えないため、**Base64 の JPEG データ URL を Firestore の文書に直接持っている**（1枚まで・70万文字以内に圧縮） |
| 送信のタイミング | 報告ボタンを押したとき 1 回だけ。更新はステータス（未対応／対応中／完了）のみ |
| 既存の外向き口 | 設定画面に Webhook URL 欄があり、送信時に JSON を 1 回 POST する（下記） |

### 保存している 1 件の形

```json
{
  "target_type":          "自作・業務アプリ",
  "category":             "勤怠・シフト",
  "quick_trouble_preset": "保存できない",
  "comment":              "保存ボタンを押しても画面が戻りません。10:30ごろから。",
  "reporter":             "ゆだ",
  "store_name":           "みなと店",
  "report_time":          "2026-09-13T10:30",
  "photo_data":           "data:image/jpeg;base64,...（無ければ空文字）",
  "webhook_endpoint":     "https://...（未設定なら空文字）",
  "status":               "未対応",
  "reporter_uid":         "（Firebase Auth の uid）",
  "created_at":           "（Firestore の serverTimestamp）"
}
```

- 文字列はすべて **日本語で保存**されます。アプリの表示は日本語・英語・ネパール語に切り替わりますが、
  保存される値と報告本文は常に日本語です。翻訳を意識する必要はありません。
- `status` は `未対応` / `対応中` / `完了` の 3 つだけです。

### 既存の Webhook が投げている JSON

`photo_data` は重いので外し、代わりに `has_photo` を立てています。

```json
{
  "content": "店舗: みなと店\n報告者: ゆだ\n対象: 勤怠・シフト\n症状: 保存できない\n日時: 2026-09-13 10:30\n\n保存ボタンを押しても画面が戻りません。10:30ごろから。\n\n(写真あり)",
  "text":    "（content と同じ文字列）",
  "report": {
    "target_type": "...", "category": "...", "quick_trouble_preset": "...",
    "comment": "...", "reporter": "...", "store_name": "...",
    "report_time": "...", "status": "未対応", "has_photo": true
  }
}
```

## 2. 連動のやり方（3案）

### 案A：Webhook で投げる（いちばん早い）

コミュニケーションアプリ側に受け口の URL を用意してもらい、報告アプリの設定画面にその URL を入れるだけ。
送る側はすでに実装済みなので、**受け口さえできれば今日から動きます。**

- ⭕ 送る側の改修がほぼ不要。プロジェクトをまたいでも問題にならない
- ⚠️ ブラウザから直接 POST するので、**受け口が CORS を許可している必要があります**（`Access-Control-Allow-Origin`）。
  許可がないと、ブラウザが送信をブロックします
- ⚠️ 写真は送れません（Base64 で数十万文字あるため）。`has_photo` が立つだけです
- ⚠️ 一度きりの POST なので、**その後のステータス変更は届きません**

### 案B：コミュニケーションアプリから Firestore を直接読む

`store-trouble-report` プロジェクトの `trouble_reports` を、コミュニケーションアプリ側から読む。

- ⭕ 写真も含めて全部見える。ステータスの変更もリアルタイムで反映される
- ⚠️ **別プロジェクトなので、読む側がそのプロジェクトで認証している必要があります。**
  読み取り専用のアカウントを 1 つ作って、コミュニケーションアプリ側で裏側からログインさせる形になります
- ⚠️ セキュリティルールは現在「ログイン済みなら全件読める」なので、そのまま使えます

### 案C：両方を同じ Firebase プロジェクトに寄せる

いちばんきれいで、将来いちばん楽。ただし移行作業が要ります。

- ⭕ 認証もデータも 1 か所。写真もステータスもそのまま共有できる
- ⚠️ 既存データの移行と、両アプリの設定差し替えが必要

## 3. 回答してほしいこと

**どれか 1 つでも欠けると実装できないので、分かる範囲で全部答えてください。**
分からない・決めていない項目は「未定」で構いません。

### (1) 土台
- コミュニケーションアプリのバックエンドは何ですか？（Firebase / Supabase / GAS＋スプレッドシート / 自前サーバー / その他）
- Firebase の場合、プロジェクト ID とリージョンを教えてください
- 料金プランは無料ですか、有料（Blaze など）ですか？
  **Cloud Functions のようなサーバー側の処理が使えるかどうかで、選べる案が変わります**

### (2) どの案で行くか
- 案A / 案B / 案C のどれが現実的ですか？　理由も一言ください
- **案Aなら**：受け口の URL と、受け付ける JSON の形を指定してください。
  上の既存 JSON をそのまま受けられるなら「そのままで可」と答えてもらえれば、送る側の改修は不要です。
  `Access-Control-Allow-Origin` を許可できるかどうかも必ず教えてください（ここが最大の落とし穴です）
- **案Bなら**：読み取り専用アカウントを用意するので、コミュニケーションアプリ側で
  別プロジェクトの Firebase を追加初期化できるか教えてください
- **案Cなら**：どちらのプロジェクトに寄せるのが良いか、移行に必要な作業を挙げてください

### (3) 受け取ったあとの扱い
- 報告はコミュニケーションアプリのどこに出したいですか？
  （専用のチャンネル／スレッド／一覧画面／通知だけ、など）
- 誰に見せますか？（全員／店長のみ／本部のみ）
- **写真は必要ですか？** 必要なら、そちらは画像をどう保持していますか
  （Storage が使えるか、Base64 を受けられるか）
- ステータス（未対応／対応中／完了）も同期したいですか？
  同期するなら、**どちらを正とするか**を決める必要があります
- コミュニケーションアプリ側から報告を更新したいですか？　それとも表示するだけで良いですか

### (4) 店舗とユーザーの対応づけ
- 報告アプリは店舗コードが `fm` ＋数字（例 `fm0001`）で、報告には店舗名と報告者名（自由入力の文字列）が入ります
- コミュニケーションアプリ側の店舗・ユーザーの識別子は何ですか？
- **`fm0001` のような店舗コードで突き合わせられますか？** できない場合、どの値で突き合わせるべきですか
