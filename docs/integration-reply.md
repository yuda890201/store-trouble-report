```
function isStoreAccount() {
  return request.auth != null
         && request.auth.token.email is string
         && request.auth.token.email.matches('^fm[0-9]{3,8}@fm[.]example[.]com$');
```

## 4. 【変更】写真は別コレクションに移しました

依頼書では「`photo_data` が報告のドキュメントに直接入っている」とお伝えしましたが、
**そのままでは無料プランの転送量が保たないことが分かったため、分離しました。**
すでに実装・テストとも完了しています。

### なぜ変えたか

`photo_data` は Base64 なので 1 件あたり最大 70 万文字（約 700 KB）あります。
そして **Firestore はドキュメントの一部だけを取ってくることができません。**
一覧を読むと、写真も全部ついてきます。

- 報告 50 件の一覧 = **10〜35 MB**（写真の枚数と大きさによる）
- 無料プランの転送量は **月 10 GiB**
- 両アプリが同じデータを読むので、早い段階で枠を使い切ります

「一覧をこまめに開く、写真を見るのは一部」という実際の使われ方に対して、
毎回すべての写真を運ぶのは割に合いません。

### 新しい形

| コレクション | 中身 | 大きさ |
|---|---|---|
| `trouble_reports/{id}` | 報告本体。**`photo_data` は入っていません。** 代わりに `has_photo`（bool） | 1 件 1 KB 程度 |
| `trouble_report_photos/{id}` | `photo_data` と `created_at` のみ。**ID は報告と同じ** | 1 件 最大 700 KB |

一覧は 50 件で 50 KB 程度になります（従来の 200 分の 1 以下）。

### そちらの実装

一覧は今までどおり `trouble_reports` を購読してください。写真だけ、扱いが変わります。

```js
// 一覧：写真は入っていないので軽い
onSnapshot(query(collection(db, 'trouble_reports'),
                 orderBy('created_at', 'desc'), limit(50)), (snap) => { ... });

// 写真：詳細を開いたときなど、必要になったときだけ 1 件読む
async function loadPhoto(report) {
  // 分離前に送られた古い報告は本体に photo_data を持っている
  if (report.photo_data) return report.photo_data;
  if (!report.has_photo) return null;

  const snap = await getDoc(doc(db, 'trouble_report_photos', report.id));
  return snap.exists() ? snap.data().photo_data : null;
}
```

**`report.photo_data` を先に見る分岐を入れてください。** 分離前に送られた報告
（数件あります）は今も本体に写真を持っており、こちらもアプリ側でその形を
今までどおり表示しています。移行はしません。古い報告は 50 件の窓から順に外れていきます。

写真を一覧のサムネイルに出したい場合は、**表示件数分だけ `loadPhoto` を呼ぶ**形に
してください。全件を先読みすると分離した意味がなくなります。
